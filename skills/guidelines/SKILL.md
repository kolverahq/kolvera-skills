# Kolvera workflow guidelines

Read [Operations contract](references/operations.md). The same rules apply in Claude, ChatGPT and Codex when the connected account exposes the required tools.

Review the selected account/desk and current records. Explain material targeting, identity or quality problems before acting. Ask targeted questions only where missing information changes the outcome; reuse already-provided answers and authorisation.

Execute authorised edits within scope without repeatedly requesting permission. Set a cap before paid discovery/enrichment and show actual spend and useful results. A scope change or higher cost needs renewed authority; another approved loop inside the cap does not.

Drafting, triaging or building a campaign does not authorise sending. Preview recipients, channel, content, sender and schedule before explicit launch. Pending-action approval can send, so reading a queue is not permission to approve all items.

Retain job IDs and terminal receipts. Diagnose uncertain or partial work before retrying. Respect suppression, private sources and candidate/client disclosure boundaries.

Report evidence, completed actions, skips and unresolved work concisely. Suggest the next specific action without silently expanding the task.
