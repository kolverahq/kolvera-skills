# Float runbook

Use with the Operations contract. This is customer-neutral; select the user's market, brand, voice, consent and commercial policy.

## Readiness and audit
Use diagnose_rmp when available to check map/desk/campaign linkage and gaps. Review source-backed capability claims, current availability, geography/work rights, compensation basis, target employers and exclusions (including current employer and sensitive competing processes).
Separate sourced fact, candidate statement and recruiter interpretation. Resolve missing evidence before publishing claims. Generic report/desk counts do not prove candidate-specific fit.

## Staged disclosure
A useful Float structure is tease -> proof -> reviewed profile/fit constraints -> optional close. Adapt touch count and timing to user and audience; do not present conversion guarantees.
Keep identity and unique employer/history details inside approved disclosure scope. Named submission needs explicit recipient/role/material consent even if anonymous marketing was previously approved.
Link or attach only the reviewed current client-facing version. Do not expose source transcripts, private notes, contractor pay or internal profitability.

## Commercial truth
Confirm currency, salary/rate period, base versus OTE, employment type and location. For contract work, private candidate pay is not the approved all-in client charge. Use the user's approved calculator/terms and label taxes/oncosts correctly. No jurisdiction-specific margin, tax or rate defaults ship in this skill. Do not infer salary demand from a market report.

## Tokens and preview
Read list_campaign_variables. A buyer-led contact's job_title can be their own title, not an advertised vacancy; never infer an open role from it.
signal may be a sentence fragment. Frame it grammatically and preview both present and absent cases. A missing variable must not produce a fabricated hiring claim.
Use approved brand/signature; avoid adding a second signature when the platform appends one.
Preview the intended sender, recipient, profile link/attachments and complete rendered message before launch. An anonymised link still needs publication review.

## Delivery modes
Creation/get email_mode is not a privacy discriminator: both private and legacy can be template. Read mode from the authorised generation response/error (private_float or private_float_review_required), preserving source provenance. Do not buy or overwrite generation only to discover mode. If unclear, stop. Legacy Float: correctly linked draft, approved inbox, reviewed enrolment while paused/draft, preview then explicit activate/confirm.
Private native Float: stable request_id plus reviewed profile and revision, exact expected_revision for regeneration; use only available private draft/edit/preview/delivery tools. Do not use shared legacy steps or legacy activation as a fallback.
Reconfirm candidate availability/authority for each new batch. Withdrawal/placement stops further candidate marketing according to explicit instruction and current campaign controls. Check suppression/collision results rather than overriding them.
