## Finding ledger

### F01 — HIGH — Remove unsafe enrichment retry recipes
Evidence: skills/contact-enrichment/SKILL.md:30 says retry stalled batch in batches of 10; :79 says one job per chat and start fresh chat. map-the-market:261 repeats retry advice; process-scrape:192 repeats chat deduplication.
Current batch_find_contacts contract: each new call creates separate run; terminal statuses include complete, partial, failed, out_of_credits, interrupted, dispatch_uncertain. It reports companies_remaining and uncertain_company_ids and explicitly forbids replaying uncertain work.
Impact: duplicate work/charges and incorrectly treating partial/uncertain outcomes as merely slow.
Action: retain job key, stop on all terminal statuses, reconcile completed/unstarted/uncertain companies, and retry only confirmed unstarted work within authorised budget. Remove fresh-chat workaround and unverified timeless timeout recipes. Include titles/seniority/function/max_per_company controls before spending.

### F02 — HIGH — Remove instruction to resume paused campaigns before enrolment
Evidence: campaign-build:122,145; rmp-campaign:174.
Production core/api/campaigns.py explicitly permits paused enrolment without scheduling sends; worker requires active campaign. Existing instruction can restart sends unnecessarily.
Action: enrol while paused; preview recipients/content; activate/resume only under explicit existing send authority. Do not equate adding recipients with permission to restart delivery.

### F03 — HIGH — Correct RMP creation/launch order and approval contract
Evidence: rmp-campaign:121 links only ICP; :151 activates before enrolling. It nevertheless asks pre-QA to confirm RMP link.
Current create_campaign supports reverse_market_profile_id and candidate_id; RMP link selects Float. activate_campaign requires enrolled contacts and first provides preview unless confirm=true.
Action: create correctly linked draft; review profile/source authority and copy; attach authorised inbox; enrol; render preview; obtain explicit launch approval; activate preview then confirm. Never treat “build” or general desk triage as permission to send. work-the-desk:43-44 must likewise distinguish reviewing pending actions from user-authorised approval that sends.

### F04 — HIGH — Replace outdated RMP Float instructions
Evidence: public rmp-campaign:124-139 prescribes old five-step full pitch and compulsory report link. Installed rmp-campaign instead delegates to rm-float-run with staged reveal, linkage, pricing/privacy and preview rules.
Current generate_campaign_steps exposes structured Float and capability-specific private draft mode; private mode needs stable request_id and reviewed profile revisions and must not use legacy polling.
Action: reconcile with reviewed current Float contract, publish required companion/reference content together, preserve candidate compensation and source privacy, and document capability-gated private mode rather than assuming all accounts use it. Never publish an internal app/report URL as an external deliverable without confirming sharing authority.

### F05 — HIGH — Fix wrong Deep Research identifier and stop logic
Evidence: deep-research:48 and map-the-market:144 pass ICP ID to expand_deep_research; actual parameter is report_id.
Current trigger_deep_research has smart fresh/expand routing and returns mode/cost/reason. Expansion history distinguishes report novelty, CRM creation and verified-fit desk additions; stop/review recommendations must be honoured.
Action: retain returned report_id; use correct expansion API; report actual cost/mode; follow polling hints and stop/review evidence, not raw novelty alone. Existing 6/4 prices mostly correct but “trigger is always fresh 6” is wrong for a desk.

### F06 — MEDIUM — Correct credit claims
Evidence: README:134-136, contact-enrichment:10, rmp-campaign:11,53, guidelines:44.
Documented intel 15 is now 23; fresh direct phone 6 is now 2; guidelines example expansion 2 is now 4; cached company-line tier 1 is omitted.
Action: update public verified costs, distinguish already-present/BYOK/cache/new discovery, and add validation against released credit constants. Do not silently modify product pricing. Date examples and prefer tool-returned actual cost when available.

### F07 — MEDIUM — Repair packaging and shared-guidelines dependency
Evidence: eight references to GUIDELINES.md do not resolve; builder packages only each individual skill folder. README calls the skill kolvera-guidelines but frontmatter/download is guidelines.
Action: make each archive self-contained for safety/approval instructions; bundle referenced guidance inside the folder, or inline small invariant sections from a generated canonical source. Use consistent names and validate every relative reference in extracted ZIPs. Do not assume installing a sibling skill guarantees it is loaded on each invocation.

### F08 — MEDIUM — Set campaign framework explicitly
Evidence: campaign-build calls create_campaign without framework, then recommends step_hints for its T.I.P.S. flow.
Current create_campaign defaults non-RMP to freeform. T.I.P.S. requires framework=tips; step_hints only apply to freeform and are ignored for structured tips/float.
Action: branch by intended framework, pass it explicitly, explain fixed structured steps versus freeform steering, and avoid pinning generation to an internal model name.

### F09 — MEDIUM — Stop labelling lifetime totals as weekly/daily evidence
Evidence: weekly-review:15 asks get_campaign_stats for “this week's numbers”; morning-briefing asks it for replies since yesterday; campaign-health asks zero sends within 48h.
Current exposed get_campaign_stats takes only campaign_id; implementation returns aggregate campaign totals without a period filter.
Action: use verified timestamped activity/deltas or an appropriate period-aware tool; otherwise clearly label totals and say period-specific evidence is unavailable. Do not invent weekly trends from aggregate counts. Explain tracking/machine-open limitations and replace rigid tiny-sample open-rate thresholds with contextual diagnostics.

### F10 — MEDIUM — Remove customer-specific targeting assumptions
Evidence: rmp-campaign:88 excludes CTO/engineering universally; icp-review:195 treats “not a software product co” as invalid; work-the-desk:33 assumes vertical SaaS.
Impact: engineering recruitment, trades, healthcare and non-software customers can have valid buyers/companies skipped or unlinked.
Action: derive buyers, industries, size and geography from selected desk/candidate/business context. Label SaaS examples as examples; do not execute them as global exclusion rules. Keep bulk cleanup approval and active-relationship protections.

### F11 — MEDIUM — Update installation and availability docs
Evidence: README:34,146 excludes Claude Free; advanced section says account skills do not sync to filesystem/Code.
Official source: https://support.claude.com/en/articles/12512180-use-skills-in-claude — Free supported; enabled account skills load in supported Claude Code versions. Distinguish that from manually copying directories.
Action: update current menus/plan prerequisites, explain account/provisioned versus local installations, retain fallback instructions, date verification and link official docs. Avoid hardcoding a permanent feature-availability statement.

### F12 — MEDIUM — Add release validation and evidence metadata
Evidence: no workflows; build-release-zips.py builds archives but has no frontmatter, dependency, contract or release freshness checks.
Action: CI for frontmatter, unique skill names, referenced files, supported tool names/parameters, current cost examples, archive root/content, and manifest/checksums. Add last_verified, compatible server release/capabilities and owner metadata. Generate/release ZIPs from one reviewed tag; verify downloads. Use a safe fixture tool catalog, never paid or sending smoke tests.

### F13 — LOW — Reduce duplicated long procedures without removing entry points
Evidence: map-the-market repeats enrichment/research/sorting logic also in focused skills; process-scrape overlaps prospect-sort/contact-enrichment.
Action: keep intent-specific entry points and concise orchestration; share tested reference sections through self-contained generated bundles. Maintain standalone uploads. Do not remove target_scoring-based S/A/B segmentation: it is distinct from retired demand scoring.
